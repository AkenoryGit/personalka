# «Персоналка» — контекст для Claude

Приложение тренера: календарь, клиенты, дневник занятий и зарплата в одном месте, плюс веб-кабинет для родителей. Тренировка вносится один раз и сразу попадает в расписание, историю клиента, кабинет и расчёт зарплаты. Первый и пока единственный пользователь — Дмитрий, тренер по плаванию в фитнес-клубе в Тюмени; приложение задумано так, чтобы потом подошло любому тренеру клуба.

- **Платформы:** Android 10+ (основной телефон — Samsung Galaxy Z Fold 8, сложенный и разложенный), затем iPhone (iOS 16+). Кабинет — браузер родителя, от 320 px.
- **Пакет:** `com.akenory.personalka` (Android и iOS) — после первой установки не меняется никогда.
- **Стек** (ТЗ 2.1, повторяет Planovo — финансовое приложение Дмитрия): Kotlin Multiplatform + Compose Multiplatform, Room KMP, Koin, kotlinx-datetime (часовой пояс клуба `Asia/Yekaterinburg`), Ktor Client; сервер — Ktor 3.1.3, Java 21, PostgreSQL 16 + Flyway, kotlinx.html для кабинета, Caddy, systemd на VPS Planovo; выкладка — GitHub Actions по SSH.
- **Модули** (ТЗ 2.2): `shared/domain` — все правила и расчёты, только здесь, с тестами по примерам ТЗ 12; `shared/data` — Room, синхронизация, копии; `shared/ui` — экраны и тема; `androidApp`, `iosApp`; `server`; `tools/import`.
- **Режимы** (ТЗ 1.5): «Только телефон» по умолчанию; «С сервером» — по приглашению. Полная копия данных всегда в телефоне.

## Сборка

- **Команда:** `./gradlew check :androidApp:assembleDebug` — тесты всех модулей, lint и APK.
- **В облачной сессии Claude** Maven Central и Google Maven закрыты, Gradle здесь не собирает, а полный лог Actions не скачивается. Код проверяется в GitHub Actions: push в ветку шага, ожидание `gh run view <id> --json status,conclusion`, итоги — отметками сборки: `gh api repos/AkenoryGit/personalka/check-runs/<job>/annotations` (номер job — `gh run view <id> --json jobs`). Отметки пишет `.github/scripts/annotate.py`: тесты по модулям, lint, состав и подпись APK, ошибки Kotlin и Gradle. В `main` — только зелёная сборка: работа шага идёт в ветке `step-N.N`, в `main` она переносится перемоткой (fast-forward). Удалить ветку на GitHub из облачной сессии нельзя — она остаётся, это не мешает. Коммиты только с документами — с `[skip ci]`, чтобы не запускать сборку и не выпускать новый APK. GitHub смотрит на последний коммит push: если шаг кончается коммитом с `[skip ci]`, `main` не пересобирается и APK в релизе остаётся прежним. Поэтому в шаге, где менялось само приложение, последний коммит перед переносом в `main` — без `[skip ci]`; запустить сборку вручную из облачной сессии нельзя (403).
- **APK:** только в релизе «Последняя сборка» из `main`, ссылка постоянная: `releases/download/latest-build/personalka.apk`. Артефакты Actions не используются: хранилище на аккаунте общее (500 МБ) и заполнено.
- **Подпись:** отладочный ключ лежит в `androidApp/debug.keystore`, поэтому каждая новая сборка ставится поверх прежней с сохранением данных. Номер версии — номер сборки в Actions.
- **Схема базы** (`shared/data/schemas`) пишется Room при сборке. В ветку шага её коммитит сама сборка («N.N: схема базы из сборки K») — после зелёной сборки сделать `git pull`. В `main` схема обязана совпадать со сборкой.
- **Общий код** в `commonMain` — только общий Kotlin, без `java.*` и Android: iOS-цели добавятся на шаге 5.1.
- **Тесты экранов** — в `shared/ui/src/jvmTest` через `runComposeUiTest`: у `shared/ui` есть JVM-цель только для них, Compose рисуется на компьютере без телефона. Логика, которой нужно состояние Compose, тоже тестируется там.

## Как работаем

- **Один шаг плана — одна сессия.** Длинный чат дорог: каждое сообщение заново читает всю переписку.
- **В начале шага** читаются только этот файл, `PROGRESS.md`, строка шага в `docs/plan.md` и разделы ТЗ, указанные у шага, — по файлу на подраздел. Если у шага есть экран — ещё `README.md` и картинки нужной папки макетов. Целиком ТЗ не читается никогда.
- **В конце шага:** тесты проходят; код закоммичен и отправлен на GitHub; в `PROGRESS.md` записано сделанное, решения, изменённые разделы ТЗ и следующий шаг; в `docs/plan.md` стоит галочка. Где есть экран, Дмитрий проверяет его на телефоне.
- **Если лимит кончается посреди шага** — остановиться на ближайшей целой точке, закоммитить и записать в `PROGRESS.md`, с чего продолжить.
- **Шаг больше, чем казалось** (больше 1–2 часов или 10–15 файлов) — делим на два и правим план.
- **Коммиты** — по-русски, с номером шага в начале: `0.10: каркас проекта и сборка APK`.

## Правила, которые легко нарушить

- **ТЗ главнее макета.** Расходятся — верно ТЗ, макет поправляется. Решение, меняющее ТЗ, вносится в файл подраздела в `docs/tz` в том же шаге и записывается в `PROGRESS.md`. Документы ТЗ и плана в Claude остались копиями на 22.10.2026 и больше не правятся.
- **Расчёты денег и статусов — только в `shared/domain`**, деньги — целые копейки (`Long`), длительности — минуты, время тренировок — локальное в часовом поясе клуба (ТЗ 3.1). Цифры в приложении и в кабинете считает один и тот же код.
- **База — Room 3** (пакет `androidx.room3`): конвертеры — `@ColumnTypeConverter(s)`, функции DAO — только `suspend` или `Flow`. Как устроены таблицы (служебные поля, даты текстом, мягкое удаление) — `PROGRESS.md`, шаг 1.1. Как только приложение начнёт открывать базу на телефоне, любое изменение таблиц — новая версия и миграция.
- **Удобство — цифрами** (ТЗ 10.7): лимит нажатий на главные действия и бюджет экрана — одна главная кнопка, не больше трёх кнопок в карточке, пустое и выключенное не показывается, на экранах только слова тренера.
- **Оранжевый #FF5A1F — ровно в пяти местах:** «+», сегодняшнее число, счётчик дел, линия «сейчас», точка «нет дневника». Контраст текста не ниже 4,5 : 1 в обеих темах (ТЗ 10.4, 10.5).
- **Персональные данные** (ТЗ 6.2, 10.3): в кабинете — только данные одного клиента, ни одного чужого имени; сведения о здоровье не собираются (нет чипа «Болезнь», подсказка «Без диагнозов…»). Оператор данных — сам тренер.
- **Реальных имён клиентов** нет ни в коде, ни в тестах, ни в макетах — только придуманные.
- **Язык интерфейса — русский:** даты «вт 22.10» и «22.10.2026», время 24 часа, «124 800 ₽» с тонким пробелом, склонение числительных (ТЗ 10.6). Все такие строки собираются функциями `shared/domain/.../format`, а не по месту.
- **Сложение Fold:** экран читает ширину из `LocalWide`; прокрутка и выбранное объявляются над веткой `if (wide)`, иначе сложение их сбросит (шаг 1.5).

## Общение с Дмитрием
