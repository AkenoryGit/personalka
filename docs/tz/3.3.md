# 3.3. Справочники и ставки

Раздел [3. Модель данных](3.md) · [оглавление ТЗ](README.md)

**Location — место:** `id`, `scope`, `name` («Большой бассейн»), `short_name` («ББ», до 4 символов), `sort`, `archived`, `color` — ключ цвета из палитры 16 цветов (`blue`, `pink`…). Тренировки места красятся его цветом, а тип выбирает оттенок (`TrainingType.shade`): по цвету тренер сразу видит, в каком бассейне работает (решение 23.10.2026, шаг 1.13в). По умолчанию ББ — синий, ДБ — розовый, Зал — коричневый; новое место получает первый свободный цвет палитры, повтор цвета разрешён с предупреждением «Этот цвет уже у места «…»».

**TrainingType — тип тренировки**

| Поле | Тип | Описание |
| --- | --- | --- |
| `name`, `short_name` | String | «Персональная», «ПТ»; короткое имя — до 8 знаков («Груд», «Кинезио»): его видно в блоке календаря и в списке клиентов |
| `kind` | `PERSONAL` / `SPLIT` / `GROUP` / `SPT` / `DUTY` / `OTHER` | Поведение в расчётах; мини-группа и грудничковое — это `GROUP` или `PERSONAL` со своим именем |
| `shade` | Int | Оттенок цвета места, которым красится тренировка этого типа: 1 — светлый, 2 — средний, 3 — яркий, 4 — тёмный. Больше четырёх оттенков одного цвета на ходу не различить, поэтому типы с одним оттенком различаются надписью в блоке. По умолчанию: ПТ 1, Сплит 2, Мини-группа 3, Группа 4, СПТ 3, Грудничковое 2, Гидрореабилитация 3, Кинезио 2; у дежурства оттенка нет (это заливка цвета места). До версии 2 базы у типа был свой цвет `color` (шаг 0.2) — с шага 1.13в его нет |
| `default_duration_min` | Int | 50 |
| `max_clients` | Int? | 1 для `PERSONAL`/`SPT`, 2 для `SPLIT`, пусто для `GROUP`, 0 для `DUTY` |
| `pay_unit` | `PER_SESSION` / `PER_CLIENT` / `PER_HOUR` | За тренировку / за клиента / за час |
| `counts_toward_pt` | Boolean | Отметка «Считать как ПТ» при создании типа; действующий список — в TierSchemeVersion.pt\_type\_ids (ПТ и сплиты — да; группы, СПТ, дежурства — нет) |
| `tier_dependent` | Boolean | Ставка меняется по ступеням |
| `diary_plan`, `diary_fact`, `diary_behavior` | Boolean | Какие поля дневника ведутся (у групп поведение выключено) |
| `split_fallback_type_id` | UUID? | Только `SPLIT`: в какой тип превращается при одном клиенте (ПТ) |
| `archived` | Boolean | Скрыт для новых тренировок, история сохраняется |

Типы по умолчанию при первом запуске: ПТ, Сплит, Мини-группа, Группа, СПТ, Дежурство, Грудничковое, Гидрореабилитация, Кинезио. Места по умолчанию: ББ, ДБ, Зал.

Короткие имена типов по умолчанию: ПТ, Сплит, Мини, Группа, СПТ, Деж, Груд, Гидро, Кинезио; места — Большой бассейн, Детский бассейн, Тренажёрный зал. Длительность — 50 минут, у группы 60, у грудничкового 30, у дежурства 240 (смена, её время задаётся при создании). Сплит по умолчанию превращается в «ПТ» (`split_fallback_type_id`). Ступени (`TierSchemeVersion`) при первом запуске не создаются: первая версия появляется при первом открытии «Зарплаты» (5.18), список «как ПТ» в ней — по отметкам `counts_toward_pt` типов.

Грудничковое, гидрореабилитация и кинезио — `PERSONAL` со своими ставками: идут в счётчик ПТ (`counts_toward_pt`) и получают надбавку по ступеням (`tier_dependent`). Грудничковое длится 30 минут и считается как 1 ПТ. В «Ставках» у таких типов есть кнопка «Надбавки как у ПТ»: ставки ступеней 2 и 3 = своя базовая + та же прибавка, что у ПТ в этом месте (цифры можно поправить). В зале ставки и надбавки те же, что в ББ: «Заполнить из сетки клуба» копирует для зала ставки ББ (у Мастер тренера ПТ 920 / 960 / 1 000, сплит 1 550 / 1 600 / 1 650).

В ДБ ставки свои: ПТ у Мастер тренера — 830 ₽. Ставки групп в ДБ и остальные ставки тренер вносит сам в «Ставках».

**RateVersion — ставка тренера**

| Поле | Тип | Описание |
| --- | --- | --- |
| `type_id` | UUID | Тип тренировки |
| `location_id` | UUID? | Пусто = для любого места (например, дежурство) |
| `valid_from` | Date | С какой даты |
| `amount_t1` | Money | Ступень 1 (или единственная ставка) |
| `amount_t2`, `amount_t3` | Money? | Ступени 2 и 3; пусто, если тип не зависит от ступени |
| `spt_close_bonus` | Money? | Только `SPT`: доплата за закрытие (140 ₽) |
| `club_service` | String? | Услуга сетки клуба (`ClubRateGrid.service`), по которой заполнена ставка: связь «мой тип × место = услуга сетки». Пусто — ставка своя. Добавлено на шаге 3.1 (версия 5 базы) |

Ставка тренировки = версия для её типа и места, действующая в день тренировки; если для места версии нет — версия с пустым местом; нет и её — тренировка помечается «нет ставки» и попадает в «Нужно сделать».

**ClubRateGrid — сетка ставок клуба** (`scope = CLUB`, шаблон для заполнения ставок тренера): `valid_from`, `category`, `service` («Персональная», «Сплит», «Грудничковое плавание»…), `location_short`, `unit`, `amount_t1`, `amount_t2`, `amount_t3`. Достаточно одной связи «мой тип × место = услуга сетки» (поле `RateVersion.club_service`), чтобы при смене категории или сетки приложение предлагало новые версии ставок. Первое наполнение — из файла «Мотивация тренеров» (15 строк: 5 услуг × 3 категории). *Шаг 3.6б (25.10.2026):* таблица встроена в приложение (`ClubRateGrid` в `shared/domain`) — услуги «Персональная», «Сплит», «Грудничковое плавание», «Малый басс Персональная», «Малый басс Сплит»; колонки «50–100», «101–150», «151+ ПТ» — ступени 1–3. «Малый басс» — ДБ, ПТ и сплит в ББ и зале — по строкам без «малого басса»; у грудничкового место не указано — одна ставка на любое место. В режиме «С сервером» сетка останется встроенной, пока не появится раздел «Клуб» (этап 5).

**TierSchemeVersion — ступени (бонусы)** (свои у каждого тренера; в режиме «С сервером» первая версия берётся из шаблона клуба): `valid_from` (1-е число месяца), `enabled`, `t2_from` (101), `t3_from` (151), `pt_type_ids` — какие типы считаются как ПТ. Выключенная схема = всегда ступень 1. Список типов хранится по версиям, поэтому его изменение не пересчитывает прошлые месяцы.
