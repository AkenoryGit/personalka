# 3.7. Кабинеты и 1С

Раздел [3. Модель данных](3.md) · [оглавление ТЗ](README.md)

**CabinetAccess — доступ к кабинету**

| Поле | Тип | Описание |
| --- | --- | --- |
| `client_id` | UUID | Для какого клиента |
| `token_hash` | Bytes | SHA-256 от токена; сам токен сервер не хранит |
| `token_local` | String | Только на телефоне, в защищённом хранилище — чтобы повторно отправлять ссылку |
| `pin_hash` | Bytes? | Argon2id от 4-значного кода, если включён. Сам код хранится только на телефоне, в защищённом хранилище рядом с `token_local` (`pin_local`), чтобы тренер мог его увидеть и переслать |
| `created_at`, `revoked_at?` | Instant | При выпуске новой ссылки старая отзывается |
| `last_opened_at` | Instant? | Когда родитель последний раз открывал (видно тренеру) |

**ConsentRecord — согласие из кабинета** (только сервер): `client_id`, `accepted_at`, `text_version`, `items` (персональные данные; фото и видео — отдельной галочкой с этапа 2), `given_by_name?` (фамилия и имя родителя из поля на экране согласия; у взрослого клиента пусто), `ip`, `user_agent`, `revoked_at?`. Нужна как доказательство того, что согласие получено и кем. Тексты согласия хранятся по версиям; новая версия текста с более широкими целями снова показывает экран согласия. На сервере — таблица `consent_record` (шаг 2.12), `items` — `personal_data` и, по желанию, `photo_video`.

**ServiceMapping1C:** `name_1c` («Персональная тренировка. ББ») → `type_id`, `location_id`.

**ClientAlias1C:** `name_1c_normalized` → `client_id`. Нормализация — раздел 8.3.

**Reconciliation — сверка:** `file_name`, `period_from`, `period_to`, `generated_at` (из имени файла), `coach_name_1c`, `rows_total`, `created_at`.

**ReconciliationItem — расхождение:** `reconciliation_id`, `kind` (`ONLY_APP` / `ONLY_1C` / `STATUS_DIFF` / `UNKNOWN_SERVICE` / `UNKNOWN_CLIENT`), `training_id?`, `row_1c` (JSON строки отчёта), `resolution` (`OPEN` / `FIXED_IN_APP` / `ASKED_ADMIN` / `IGNORED`), `resolved_at?`.
