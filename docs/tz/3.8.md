# 3.8. Служебные таблицы

Раздел [3. Модель данных](3.md) · [оглавление ТЗ](README.md)

| Таблица | Где | Поля |
| --- | --- | --- |
| Outbox — очередь изменений | Телефон | `entity`, `entity_id`, `version`, `queued_at`, `attempts` |
| SyncState | Телефон | `last_pulled_seq`, `last_sync_at`, `last_error` |
| Account | Сервер | `coach_id`, `email`, `password_hash` (Argon2id), `role`, `status` (`ACTIVE` / `SUSPENDED`), `club_id` |
| Session | Сервер | `token_hash`, `coach_id`, `device_name`, `created_at`, `last_seen_at`, `expires_at` |
| Invite | Сервер | `code_hash`, `created_by`, `expires_at`, `used_by?`, `used_at?` |
| ChangeLog | Сервер | `seq` (сквозной номер), `coach_id` или `club_id`, `entity`, `entity_id`, `version` |
| AppRelease | Сервер | `platform`, `version_code`, `version_name`, `url`, `sha256`, `notes`, `min_supported_code` |

*Изменено на шаге 2.9 (24.10.2026):* ChangeLog на сервере — таблица `sync_row`: сама запись телефона (`owner` — тренер или клуб, `entity`, `id`, `version`, `updated_at`, `deleted_at`, `device_id`, `data` в JSON) вместе с её последним `seq`. Отдельного журнала нет: устройству нужно последнее состояние записи, а не все её правки.

*Изменено на шаге 2.10 (24.10.2026):* Outbox на телефоне — таблица `sync_outbox` (`entity`, `rowId`, `updatedAt` — момент последней правки записи), ключ — таблица и id: повторные правки склеиваются в одну строку. Пишут её триггеры SQLite в той же транзакции, что правку; отправляется запись целиком такой, какая она в таблице в момент отправки, поэтому `version` и `queued_at` не нужны; `attempts` — общий счётчик ошибок обмена, а не у строки. SyncState — не таблица, а настройки телефона (`DevicePrefs`: `sync.connected`, `sync.since` — последний полученный `seq`, `sync.last`, `sync.device`): в копию и на другой телефон не попадает. Таблицы `sync_…` — только для телефона: не синхронизируются и не входят в резервную копию.
