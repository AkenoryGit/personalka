# 4.9. СПТ (стартовая тренировка)

Раздел [4. Бизнес-правила и расчёты](4.md) · [оглавление ТЗ](README.md)

1. СПТ отмечена проведённой → создаётся SptCase `OPEN`, `window_until` = та же дата следующего месяца (31 января → 28/29 февраля).
2. В месяце СПТ начисляется базовая ставка (200 ₽).
3. Тренер нажимает «Купил блок со скидкой» и указывает дату покупки. Дата ≤ `window_until` → `CLOSED`, доплата `spt_close_bonus` (140 ₽) идёт в **месяц покупки**. Дата позже — нельзя сохранить, статус `NOT_CLOSED`.
4. Первая оплаченная ПТ того же клиента у того же тренера, пока окно открыто → подсказка «Засчитать СПТ закрытой?» с датой покупки = дата тренировки (можно поменять).
5. Окно закончилось без отметки → `NOT_CLOSED`. Если позже клиент придёт на первую платную ПТ → вопрос «Блок был куплен со скидкой до {window\_until}?»; «Да» + дата в окне → `CLOSED` задним числом.
6. За 3 дня до конца окна — напоминание «Уточните, купил ли … блок».

Конверсия стартовых = `CLOSED` / (`CLOSED` + `NOT_CLOSED`) за период.

- Уточнения шага 3.4 (25.10.2026): дата покупки со скидкой — не раньше дня СПТ и не позже `window_until` включительно; иначе её нельзя сохранить. Окно, прошедшее без отметки, даёт `NOT_CLOSED` и тогда, когда в базе ещё `OPEN` (слой данных переписывает его по `SptRules.expired`). Закрыть задним числом можно и `NOT_CLOSED`; снятая отметка покупки возвращает `OPEN`, если окно не прошло, иначе `NOT_CLOSED`. Доплата — `spt_close_bonus` ставки типа и места СПТ, действующей в день СПТ (а не в день покупки); нет суммы — 0. Доплата входит в «Заработано», «Начислено» и прогноз месяца покупки. Вопрос на ПТ задаётся только на первой оплаченной ПТ клиента в день СПТ или позже; закрытому делу — никогда. Напоминание — с `window_until` − 3 дня по `window_until`, пока дело открыто. Конверсия — по СПТ, проведённым в периоде, со статусом на сегодня; открытые не считаются; нет решённых — не показывается. Расчёт — `SptRules` в `shared/domain/money`.
