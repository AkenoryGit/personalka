# 7.7. Обновления приложения

Раздел [7. Сервер и синхронизация](7.md) · [оглавление ТЗ](README.md)

- **Android:** раз в сутки приложение спрашивает `/app/latest`. Новая версия → плашка «Доступна версия 1.3: что нового. Обновить» → загрузка APK с домена, проверка SHA-256, системный установщик. Версия ниже `min_supported` — блокирующий экран с кнопками «Обновить» и «Сохранить резервную копию». Позже — публикация в RuStore.
  - *Шаг 5.33 (21.11.2026):* пока нет RuStore и `/app/latest`, обновление — кнопкой «Ещё → О приложении → Проверить обновление»: приложение читает описание релиза «Последняя сборка» на GitHub (репозиторий открытый; в описании «Сборка N», его пишет `build.yml`) и сравнивает N со своим номером сборки. Новее — «Скачать» открывает постоянную ссылку на APK в браузере, APK ставится поверх (тот же ключ), данные сохраняются. Ежедневной проверки, плашки и блокирующего экрана пока нет. В запросе к GitHub — ничего о тренере.
  - *Замечание Дмитрия 22.11.2026:* при выкладке в RuStore или Google Play кнопку переделать — в сборке из магазина она не качает APK с GitHub, а открывает страницу приложения в магазине или убирается (магазин обновляет сам; Google Play запрещает обновление в обход него). На iPhone кнопки нет и в App Store не будет — обновляет App Store или TestFlight.
- **Ключ подписи APK** хранится в двух местах вне репозитория: без него нельзя выпустить обновление без переустановки.
- **iPhone:** TestFlight; новая сборка не реже раза в 80 дней (сборка действует 90).
- Миграции локальной базы выполняются при запуске; перед миграцией автоматически создаётся резервная копия.
