# 8.4. Результат и действия

Раздел [8. Сверка с 1С](8.md) · [оглавление ТЗ](README.md)

Сводка: «Совпало 189 · Расхождений 4». Списки и действия:

| Список | Действия |
| --- | --- |
| Только в 1С | «Добавить в приложение» (со статусом из 1С), «Игнорировать» |
| Только в приложении | «Написал администратору», «Исправить в приложении», «Игнорировать» |
| Статус или услуга расходятся | «Исправить в приложении» (как в 1С), «Написал администратору», «Игнорировать» |

- «Скопировать для администратора» собирает выбранные пункты в текст: «08.10 09:00, группа, Пестов Егор — был на тренировке, в 1С «Отменил». Прошу исправить».
- Пункты «Написал администратору» через 3 дня напоминают о себе. Открытые расхождения видны в «Нужно сделать».
- Повторная сверка за тот же период сама закрывает исправленные пункты.

*Шаг 4.2, 26.10.2026 — уточнения:* строка для администратора по видам: статус — «…, в 1С «Отменил». Прошу исправить»; услуга — «…, в 1С «Сплит. ББ». Прошу исправить»; «Только в приложении» — «…, в 1С нет. Прошу добавить». Пункты «Только в 1С» и не отмеченные в приложении тренировки исправляются в приложении — в текст для администратора не попадают. «Был / была» — по полу клиента, без пола — «был(а)». Повторная сверка: пункт, который пропал, закрывается сам, если был открыт или «Написал администратору»; «Игнорировать» у того же пункта сохраняется (`Reconcile1cRules.carry`).

*Шаг 4.2в, 26.10.2026 — экран:* «Ещё → Сверки» → строка сверки в карточке «Отчёт 1С» (после загрузки экран открывается сам). Сверху период, «Совпало N · Расхождений M» (только нерешённые) и «Отправить администратору»; ниже три списка, пункт — «чт 08.10 · 09:00 · Пестов Егор» и подпись «в приложении: Группа · ДБ · был на тренировке · в 1С «Отменил»». Нажатие — окно с действиями (не больше трёх кнопок, 10.7):

- **Только в 1С:** «Добавить в приложение» — клиент добавляется в тренировку того же типа, места и начала, если она есть (группа), иначе заводится новая тренировка тренера с длительностью типа; «Пришел» — проведена, «Отменил» — отменена. Неизвестный клиент заводится по ФИО из 1С, имя запоминается. «Игнорировать».
- **Только в приложении:** «Исправить в приложении» — участие становится отменой без списания; «Написал администратору»; «Игнорировать».
- **Статус или услуга:** «Исправить в приложении» — статус участия как в 1С («Пришел» → проведена, у тренировки — «Проведена»), услуга — тип и место тренировки из ServiceMapping1C; «Написал администратору» (у не отмеченной в приложении тренировки нет — её исправляет тренер); «Игнорировать».

«Отправить администратору» вместо выбора пунктов галочками: одним нажатием собирает строки всех открытых пунктов, которые исправляет администратор, отдаёт текст в «Поделиться» и отмечает их «Написал администратору» — меньше нажатий (10.7). «Нужно сделать» (5.2): «Расхождения с 1С» — «открыто: 3 · администратор не ответил: 1» (отмеченные «Написал администратору» больше 3 дней назад), нажатие — «Сверки». Решённые и игнорированные пункты на экране не показываются.
