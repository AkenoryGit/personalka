# 9.5. Второй запуск: дозагрузка дневника

Раздел [9. Разовый импорт из таблиц](9.md) · [оглавление ТЗ](README.md)

> Импорт отменён 23.10.2026 — см. [раздел 9](9.md).

На этапе 1 в приложении уже работают календарь и клиенты, а План / Факт / Поведение и результаты ещё ведутся в Google-таблицах (дневник появляется на этапе 2). Второй запуск переносит эти записи в приложение и не трогает расписание.

- **Вход:** свежая копия приложения (Настройки → Резервная копия), папка xlsx и файл сопоставления от первого запуска.
- **Клиенты** сопоставляются по связкам из файла сопоставления; новые — по нормализованному имени (регистр, ё→е, лишние пробелы). Ненайденные попадают в отчёт; утилита их не создаёт, решение записывается в файл сопоставления.
- **Тренировки** сопоставляются по клиенту и дате (и времени, если оно есть в таблице). Если у клиента в этот день несколько тренировок в приложении — строка уходит в отчёт для ручного выбора.
- **Что заполняется:** только пустые поля «План», «Факт», «Поведение» и причина отмены. Если поле в приложении уже заполнено и отличается — остаётся текст приложения, расхождение уходит в отчёт. Результат добавляется, если в приложении нет результата с той же датой и дистанцией.
- **Что не меняется:** статусы, время, места, серии, деньги. Строки таблицы без пары в приложении только попадают в отчёт: после месяца перехода главный — календарь приложения.
- **Выход:** новый файл копии. Сначала режим проверки с отчётом (как в 9.4), потом сборка. Если версия схемы в копии утилите неизвестна, она отказывается работать.
- **На телефоне:** между созданием копии и её восстановлением в приложении ничего не вводить — восстановление заменяет все данные. Второй запуск делается до подключения к серверу.
